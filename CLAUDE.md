# Repository Guidelines

## Project Status & Structure

Agent Monitor is a macOS Swift monitor for mapping heavy processes to specific coding-agent sessions. `Sources/AgentMonitorCore/` contains native sampling, attribution, and models; `Sources/AgentMonitor/` contains the command-line harness; `AgentMonitorPresentation/` owns neutral rendering/interaction state and `AgentMonitorTUI/` owns SwiftTUI views. `AgentMonitorActions/` owns verified process termination and provider messaging. `AgentMonitorMenuBar/` owns the native AppKit/SwiftUI menu bar app; reuse core, presentation and action services without importing SwiftTUI. `Tests/` contains Swift Testing tests and disposable process fixtures. [TUI research](docs/research/terminal-ui.md) records the isolated probe; its temporary build directory has been removed. Keep UI dependencies out of the monitoring core. See [README.md](README.md), [development guidance](docs/development.md), and [current scope](PLAN.md#scope-and-pending-decisions).

`CLAUDE.md` is canonical; preserve the `AGENTS.md` symlink.

Keep research notes limited to dated observations, source evidence, explicitly labeled inferences and unresolved empirical questions. Consult the [research index](docs/research/README.md) before investigating, extend the matching note, and index every new note or retained measurement in the same commit. Put accepted contracts in [architecture](docs/architecture.md), usage in the [usage guide](docs/usage.md), open work in [PLAN.md](PLAN.md), and unapproved designs in `docs/proposals/` with their status. Research must not contain implementation plans, task lists, effort estimates or declarations of product scope. Preserve source/version provenance and uncertainty when condensing; editing a note does not revalidate its external sources.

Keep the [README](README.md) focused on users: purpose, features, quick start, and current support. Detailed controls belong in the [usage guide](docs/usage.md), build/check instructions in the [development guide](docs/development.md), and implementation contracts in the [architecture document](docs/architecture.md).

When changing CLI options, defaults, or incompatible combinations, update the README option table and affected usage examples in the same commit. Verify them against `Options.swift` and the executable's generated `--help`, including the different default sample count in TUI mode.

Read [PLAN.md](PLAN.md) when resuming. Keep it limited to unfinished work, scope decisions and concrete next actions; remove completed entries once their durable outcome is documented. Record release evidence in release notes, repeatable checks and coverage limits in the [development guide](docs/development.md#validation-coverage), and unique measurements beside their research data. Do not recreate an append-only validation or completed-task log. Process termination, Codex/Claude messaging, adapter-based terminal focus (Terminal.app first) and their CLI subcommands are authorized and shipped; unrelated product expansion remains out of scope.

Follow [architecture boundaries](docs/architecture.md): monitoring logic and snapshots are UI-independent; text, TUI, and native views own presentation only. Document architectural changes alongside the code.

Everything specific to one agent harness belongs to its adapters; see [harness adapters](docs/architecture.md#harness-adapters). Provider recognition, marker keys/validation, writer-lock or inbox interpretation, session-listing commands and their parsing, and provider-specific runtime classification belong exclusively in the built-in [attribution adapters](Sources/AgentMonitorCore/AttributionAdapters/). Extend the adapter contract only for a concrete observation needed by a provider. Do not add provider-specific attribution branches or executable/environment recognition heuristics to `Monitor`, `NativeProcessReader`, `ProcessArguments`, models or presentation; model conveniences delegate to the registry. Native access and input allowlisting remain in the host, while adapters consume declared observations and report evidence. Messaging and focus keep their separate action adapters.

Preserve all recognition claims: reject duplicate provider registrations and never choose a runtime owner by adapter order. New recognition rules need exact positive attribution plus negative/conflicting fixtures; adapter changes must retain nested-provider, detached-worker, PID-reuse and malformed-marker guards. Provider columns, sorting and filtering consume the resolved attribution, never a second recognition implementation. See [adapter development](docs/development.md#changing-attribution-adapters).

When changing dependency or optional skill pins, update [third-party notices](THIRD_PARTY_NOTICES.md) from the locked upstream sources, including vendored components and font notices. Preserve the notice index and original licenses in release archives; see [release packaging](docs/releasing.md).

Before extending a feature, check its documented ownership boundary. If the current code bypasses that boundary, make the smallest authorized extraction as part of the change; surface a material scope conflict before building on the bypass. Do not silently leave an accepted architecture as a proposal while expanding the old path. In the same commit, keep architecture status, source ownership, contributor guidance and completion evidence aligned, and clearly separate implemented contracts from deferred capabilities.

Session grouping belongs to presentation and totals only displayed heavy processes. Project labels use workloads’ working directories, never a shared runtime’s launch directory; shared runtimes claim no project. Different workload directories display “Multiple directories”; nesting does not establish a shared project root. Preserve provider/session identities and attribution uncertainty; never merge by directory or shared runtime alone. Keep JSONL's flat snapshot contract independent of grouping.

## Build, Test, and Development Commands

- `swift build`: build the library and executable.
- `swift run agent-monitor`: report heavy consumers.
- `swift test`: run unit and native integration tests.
- `swift format lint --strict --recursive Sources Tests Tools Package.swift`: check formatting.
- `bash scripts/doctor.sh`: check the contributor toolchain and optional skill setup without installing anything.
- `bash scripts/preview.sh check`: verify the README preview matches the production layout and synthetic fixture.
- `python3 scripts/verify-poc.py "$(swift build --show-bin-path)/agent-monitor"`: verify controlled terminal attribution after building.

Use Xcode 27, Swift 6.4, and macOS 27. Apple Argument Parser belongs only to CLI targets; keep the monitoring core independent of it and UI libraries.

## Coding Style & Naming Conventions

Project skills must work with both Codex CLI and Claude Code. Keep one canonical copy with its references and license; expose it through both hosts' skill discovery directories, using symlinks where appropriate. Keep host-specific hooks, plugins, and tool configuration separate, and verify both discovery paths before adopting a skill.

Use `bash scripts/skills.sh install` for project-local skills, `update` for explicit upgrades, and `check` to verify both discovery paths. Preserve the generated `skills.lock`; see [skill setup](docs/development.md#skills-shared-by-codex-cli-and-claude-code).

Use `swiftui-view-refactor` for native view structure/dependency/Observation reviews and `swiftui-performance-audit` for rendering, refresh and scrolling investigations. Both share the pinned `agent-scripts` source; retain the existing concurrency/testing skills. Preserve AppKit-owned lifecycle and shared core/action boundaries even where upstream examples prefer view-owned state. Treat performance suspicions as hypotheses until measured. Apple guidance and [native menu research](docs/research/native-menu-design.md) govern platform design; upstream personal instructions, hooks and release automation are not adopted. Keep [trial findings](docs/research/development-tools.md#first-project-trial--2026-10-15) distinct from accepted contracts and open work.

On a fresh clone, the tracked skill symlinks do not resolve until `install` populates ignored `.skill-sources/` at the locked revisions. Skills are optional development aids, not build/runtime dependencies. Do not commit those source checkouts, change the lock during routine setup, or install skills globally. The read-only doctor reports missing skills as optional and broken installed skills as an error.

Keep left-click for the panel and right-click/Control-click for the status menu. Reuse option commands between the panel and status menu, and expose load explanations through the menu and accessibility text. Keep native View options menu tracking independent of report refreshes: preserve the AppKit button/menu and rebuild entries only before opening, never while tracking. Preserve checked current values, including values outside the presets. Inherit system light/dark appearance with semantic colors and template status images; do not force a theme or poll appearance. Live rows and unavailable pin placeholders share `MenuBarPinButton`; keep its appearance and unpin action consistent across sampling states. Reserve native row chevrons for session children, show a prominent heavy-process count badge, and use an info control for process details. Keep the whole header clickable and retain enlarged pointer targets. Share browsing keys through `ReportShortcut`: `.` pins and `p` pauses in both views. Native row actions and `y`/Copy PID require the exact visible process identity; keep browsing keys out of action panels and text entry. See [native interaction contracts](docs/architecture.md#native-menu-bar-app).

Keep the generated [README preview](docs/assets/tui-preview.svg) current when changing layout, displayed text, grouping, details, or synthetic fixtures. Run `bash scripts/preview.sh update`, visually review the SVG, and commit it with the change; then run `bash scripts/preview.sh check`. Edit [the generator and fixture](Tools/Preview/), never the SVG by hand. Use synthetic identities and paths only; never sample real processes for documentation images. The generator is development-only and must not be included in release archives. CI runs preview drift checks and Swift tests on every pull request and main push. The SVG verifies text/layout, not terminal interaction or exact theme colors; preserve PTY tests and visually review TUI style changes. See [preview maintenance](docs/development.md#readme-preview).

Preserve fixed character positions in the preview SVG; do not stretch rows with `textLength`/`lengthAdjust` or rely on whitespace preservation for terminal columns. Verify browser appearance headlessly using a fresh, isolated temporary profile. Never open or bind the user's browser apps, windows, tabs, or profiles for verification. State explicitly when only a converter render was inspected.

Keep the additional [native panel screenshot](docs/assets/menubar-preview.webp) alongside the TUI preview, using the synthetic offscreen render described in [development](docs/development.md#menu-bar-app); it does not establish live menu anchoring. Size documentation images for their displayed dimensions, allowing 2× resolution for raster icons. Use optimized web assets rather than full-resolution generated masters; check file size and visual quality before committing. The README logo is a 256 × 256 WebP displayed at 128 × 128. Keep explicit display dimensions and descriptive alternative text.

Use four-space indentation, the bundled `swift format`, Swift 6 concurrency checking, and enum-based switches. Keep presentation separate from collection. Comments explain constraints and cite their basis. Write Markdown with one paragraph per physical line and regular links to other documents.

## Testing Guidelines

Headless checks are the default for native development: exercise core/presentation/model behavior with deterministic inputs, fake provider transports and controlled clocks, then verify native layout with synthetic offscreen AppKit renders. Reuse production composition when testing across layers. Do not require Computer Use, desktop automation, real harness listings or live messages for routine validation. Offscreen AppKit still requires a suitable macOS environment; it does not prove physical input delivery or menu anchoring.

The user has disabled Computer Use and owns the [manual macOS smoke test](docs/development.md#manual-macos-smoke-test). Do not request or enable Computer Use for routine review. Keep live smoke results explicitly pending until the user reports them; automated success does not close that gate. Reserve extended provider delivery/focus, accessibility and energy checks for the specific changes or claims that need them, using disposable targets where applicable.

Use red/green TDD and descriptive Swift Testing tests. Positive fixtures must resolve exact sessions; unknown everywhere cannot pass. Cover same-directory sessions, PID reuse, detached children, ambiguity, and resource-unit semantics. Never infer ownership from cwd alone or treat a protocol process handle as an OS PID.

Action execution belongs in `AgentMonitorActions`, never the sampler or UI. Preserve frozen PID/start/executable identity, fresh same-user checks, confirmed single-process SIGTERM, exact live recipient verification, root default without fallback, and automatic workload PID/resource/sample-time context. Keep the selected observation frozen through preparation and restored drafts; native Copy message must match review and Send exactly. Treat queue acceptance separately from delivery; never automatically retry an uncertain send. Use fake provider transports and disposable owned processes in tests; do not signal real workloads or send test messages to live agents. Codex `app-server proxy` forwards WebSocket bytes, not the JSONL used by a standalone stdio app server; keep handshake/framing regressions and verify actual read-only transport when changing it. Terminal focus adapters may only read session identities, select, unminimize, order and activate; never type, run scripts in, or read a terminal, and test with fake adapters and a fake `osascript` rather than driving real terminals. Never read or send a Claude session's messaging token; verify the runtime PID/session binding with `claude agents --json` before preparing and sending. Keep bracketed paste separate from command input and prevent confirmation when the action panel is hidden by a small viewport. Cancel and reap owned provider subprocesses on shutdown. See [action architecture](docs/architecture.md#process-and-session-actions).

## Commit & Pull Request Guidelines

Git is initialized on `main`. Build outputs, caches, and temporary evaluations must remain ignored. Use Conventional Commits, such as `feat(attribution): identify heavy session workloads`. Add a concise body for non-obvious rationale.

Automatically commit completed, validated checkpoints and relevant features without asking for confirmation. Keep each commit coherent, include related documentation, and leave unrelated work untouched. This project-specific authorization overrides the global preference to only propose commits for fixes; it does not authorize pushing.

Pull requests should describe the problem, resulting behavior, and validation performed. Link applicable issues and include screenshots for visible UI changes. Do not create or switch worktrees without explicit instructions.

## Menu bar app

The native menu bar app is a maintained source-built feature alongside the CLI and TUI: a menu-bar-anchored popover with optional AppKit drag detachment, a live three-bar status icon with one 250 ms startup sample followed by 15-second closed-panel sampling and an optional static icon that disables closed-panel sampling. Keep native controls separate from terminal layout, reuse neutral grouping/selection/action review and verified action services, cancel actions on dismissal and drain all owned tasks on quit. Live mode keeps one collector and its baseline across dismissal, using the selected interval (5 seconds by default, also in the TUI) while open; static mode cancels collection on close and starts a fresh baseline on reopening. Keep collection and action generations separate. The opt-in core agent-load summary is independent of report filters, pins and pause; table sampling and the JSONL contract stay unchanged. The bars and numeric badge derive from filtered findings, matching the displayed table and its pause state while open; closed mode uses the latest collected findings. Count distinct process lifetimes once, including collapsed groups and singletons but not missing pins. History retains its independent all-agent summary and 15-second enrichment cadence. Keep the same three-bar icon at startup, during collection failures and in static mode; missing measurements have no count and are explained in the status menu. Keep the smaller monochrome badge at the upper left with a clear gap above the shortened bars within the fixed 18-point icon, cap its text at 99+ and retain the exact count in the status menu/accessibility label; never widen the item or invert the bars as an event cue.

Keep the user-chosen panel height fixed across content changes, with scrolling and a screen-fit cap on opening. Keep keyboard help behind View options and inside that same scroll area. Reuse neutral snapshot freeze state for native Pause/Resume; keep paused status and the resume control visible. Keep pins and View options in shared presentation state, preserve native choices across dismissal until quit, and feed sampling controls through the existing live threshold/interval contract. Pins retain identities and labels only; unavailable targets must not display old measurements or execute actions. Stable order is the GUI/TUI default: preserve surviving process/session order, append new identities, keep pins above the list and preserve order across native dismissal. Switching from another sort freezes its current order; reverse has no effect in Stable order. TUI `o` selects Stable order, `.` toggles pins, `p` pauses, and `n` sorts by PID; native `.` pins focused rows, ←/→ collapses/expands rows, and Return/Space retain native control activation.

Keep unsent draft text separate from executable action state and reverify the original target/recipient when resuming; automatic dismissal must not discard it.

Build the optimized local bundle with `bash scripts/menubar.sh build` (`AGENT_MONITOR_BUILD_CONFIGURATION=debug` selects an unoptimized bundle); use `run` to pass the shell PATH to provider transports. Production distribution, login items, background services and notifications remain out of scope. See [architecture](docs/architecture.md#native-menu-bar-app) and [validation limits](docs/development.md#menu-bar-app).

Native arrival highlights belong to presentation: compare displayed process/session identities, suppress initial population, highlight both new children and their parent session headers (including collapsed parents), expire after three seconds without renewing on reorder or disclosure, and cancel expiry on dismissal. Use semantic grayscale and honor Reduce Motion; no extra sampling or recurring timer. Row context menus reuse the same reviewed action flows as expanded controls and dim unavailable commands. Snapshot eligibility for messaging/focus comes from the action service’s execution prerequisites; menu construction must not inspect live processes or contact providers.

History belongs to neutral presentation, using the existing all-agent summary in TUI and native modes. Keep one strip, CPU/10 minutes by default, with memory/count and one-hour choices; preserve bounded scalar storage, peak compression, gaps, paused inspection and no extra sampling timer. Collect the all-agent summary on the first sample and then at most every 15 seconds on existing table samples; between summaries, use ordinary threshold enrichment and retain the last history value and its measurement time; icon values follow the displayed findings independently. Native history menus reuse stable AppKit tracking. Keep a subtle native chart baseline even when empty and label an unavailable current measurement “No data”, distinct from numeric zero. Text/JSONL must not enable the summary for this feature. See [resource history](docs/architecture.md#resource-history).

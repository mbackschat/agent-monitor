# Agent Monitor 0.2.2

Released 2026-10-15.

A maintenance release for detached Codex workloads and clearer shared-runtime attribution.

## Changed

- **Detached Codex jobs reconnect to their session runtime.** A surviving job's exact thread marker can match one live runtime's writer descriptor after its launching shell exits. Process lifetimes and ambiguity checks prevent guessing between runtimes.
- **Shared Codex daemons have an explicit label.** A runtime holding multiple thread writers appears as `codex/shared runtime`; workloads with an exact session keep that session attribution.
- Provider recognition, marker validation and runtime evidence interpretation now belong to built-in Codex and Claude attribution adapters. Architecture and contributor guidelines define this boundary and its regression checks. This internal change preserves the CLI and JSONL contracts.

## Install

Download `agent-monitor-0.2.2-macos-arm64.tar.gz` and its `.sha256` checksum, or upgrade with `brew upgrade mbackschat/tap/agent-monitor`. See the [installation guide](https://github.com/mbackschat/agent-monitor/blob/v0.2.2/docs/installation.md).

Requires **Apple Silicon and macOS 27**. Xcode is not needed to run the download. Source builds require Xcode 27 with Swift 6.4.

The binary is ad-hoc signed, not Developer ID signed or notarized. macOS may block downloaded copies; source-build instructions are provided as an alternative.

## Scope and limitations

Shared daemons are not mapped to individual terminal clients. Real terminal Codex workload validation remains a coverage limitation; detached-shell behavior is verified with controlled native fixtures. Provider columns, sorting and filtering are not added in this release.

Other limitations remain as described in [0.2.0](https://github.com/mbackschat/agent-monitor/blob/v0.2.0/docs/releases/0.2.0.md#scope-and-limitations): accepted actions are not confirmed outcomes, Claude Code's inbox message format is undocumented, only Terminal.app tabs are selected when focusing, and attribution describes launch origin.

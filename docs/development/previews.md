# Maintain documentation previews

The TUI SVG follows presentation changes; the tracked Mac panel WebP changes only for releases. Both use synthetic production composition. Keep intermediate native review PNGs in ignored `.build/design-studies/`.

[Development guide](../development.md) · [All development references](README.md)

## TUI preview

The [preview script](../../scripts/preview.sh) builds the development-only `monitor-preview` target. Its [synthetic ledger fixture](../../Tools/Preview/LedgerFixture.swift) feeds the production `MonitoringSession`, recent-activity store, `LiveReportState` and `LiveReportLayout`; the [SVG generator](../../Tools/Preview/Preview.swift) adds illustrative terminal decoration. It never samples processes or reads agent sessions.

The fixture shares one synthetic clock across collection and metadata, supplies identity through synchronous launch capture, and acknowledges each report before advancing the next acquisition. Fixed identities, measurements, twelve one-second intervals and a 120 × 32 viewport make the rendered output reproducible without real-time sleeps.

```sh
bash scripts/preview.sh update
bash scripts/preview.sh check
```

`check` regenerates in memory and compares bytes; missing or different output fails with the update command and leaves the asset untouched. Run it when presentation, grouping, details, labels or fixture changes can affect the generated preview.

### Update and inspect

`update` replaces [the SVG shown in README](../assets/tui-preview.svg); if the preview changes, regenerate it, inspect spacing/clipping/legibility in an isolated headless browser, commit it alongside the change and rerun `check`.

Edit [the generator and fixture](../../Tools/Preview/), never the SVG by hand. Use synthetic identities and paths only, never live samples for documentation images.

README embeds SVG directly, so there is no second PNG to synchronize and no converter or font package to install.

### Chart and text geometry

Browser text-font appearance can vary; chart blocks use exact eighth-cell SVG rectangles, so partial caps meet the filled row below independently of font fallback. Three stacked chart rows retain 24 height steps; missing/zero/monochrome overflow markers remain text. The asset's cell geometry and generated bytes are deterministic.

The generator places each visible grapheme at its terminal-cell coordinate and leaves spaces as gaps. Do not fit whole rows with SVG `textLength` or `lengthAdjust`: glyph scaling can distort the font, and collapsed whitespace can change the apparent column widths.

Keep the fixed-cell and fractional-chart boundary regression tests, and check three-row bars for internal gaps in an isolated headless browser; a converter rendering alone does not establish browser compatibility.

Use a fresh temporary profile, never an existing user browser or profile. Headless Chrome with `--disable-gpu --run-all-compositor-stages-before-draw` successfully rendered the published SVG during verification; GPU-backed capture was blank in this environment.

### CI and fixture coverage

[CI](../../.github/workflows/verify.yml) runs on every pull request, main push, and manual dispatch, avoiding path filters that could miss a new dependency. It runs the documentation checks, Swift suite, formatting, preview check, and offline skill-installer tests. The [Xcode 27 runner](https://github.com/actions/runner-images/blob/main/images/macos/xcode-27-arm64-Readme.md) supplies the required macOS SDK and Swift toolchain; the workflow selects Xcode 27.0 explicitly. No skill download is needed for CI. A stale preview fails the check; CI does not rewrite or commit assets. Requiring the check before merges is a separate repository branch-rule setting.

[Preview tests](../../Tests/PreviewTests/PreviewTests.swift) exercise missing/stale asset detection, XML escaping, and process/session layouts at 60, 85, 120, and 160 columns.

The ledger guard holds asynchronous metadata until the final report, checks first-interval session ownership and retained exited-worker history across all twelve intervals, and compares the final SVG with immediate metadata. This guarantees the rendered fixture contract, not identical internal metadata timestamps.

The preview represents one illustrative state, not every interaction or exact terminal theme. Keep the existing layout and PTY tests, and review style-only TUI changes visually even if the SVG bytes do not change. `monitor-preview` is not part of the installed CLI or release archive.

### Fixture provenance

PREVIEW-01 was resolved on 2026-10-29: deliberately delaying metadata made the previous fixture's first report lose all seven agent contributors; synchronous launch evidence and controlled acquisition/publication remove that scheduling dependency. The published SVG remained byte-identical. An earlier isolated stale check did not retain its differing output, so this reproduction does not establish that incident's exact cause.

### Asset size and release policy

Size documentation images for their displayed dimensions, allowing 2× resolution for raster icons. Keep optimized web assets rather than full-resolution masters, and check file size and visual quality before committing. The README logo is a 256 × 256 WebP displayed at 128 × 128; preserve explicit display dimensions and descriptive alternative text.

The native header bundles the same artwork in [its resources](../../Sources/AgentMonitorMenuBar/Resources/agent-monitor.webp); the resource test requires byte equality with the README asset, so update both copies together.

Keep the additional [native panel screenshot](../assets/menubar-preview.webp) alongside the TUI preview. Update this tracked WebP only during [release preparation](../releasing.md#release-in-three-steps), using the [synthetic offscreen render](native-app.md#build-and-coverage-details); intermediate review PNGs stay in ignored `.build/design-studies/`. This limits binary history growth and does not establish live anchoring.

## Native release screenshot

The additional [README native screenshot](../assets/menubar-preview.webp) comes from the production SwiftUI hosting view with synthetic identities and measurements, showing Main contributors and recent activity. Refresh the tracked WebP only for releases; ordinary native UI changes still need visual review, with PNGs kept in ignored `.build/design-studies/`. The generated TUI SVG keeps its existing per-change drift check. Render native review images with:

```sh
mkdir -p .build/design-studies
TZ=UTC MENUBAR_OVERVIEW_PREVIEW_PATH="$PWD/.build/design-studies/menubar-preview.png" swift test --filter nativeContributorOverviewRenders
TZ=UTC MENUBAR_PREVIEW_PATH="$PWD/.build/design-studies/menubar-processes.png" MENUBAR_ICON_PREVIEW_PATH="$PWD/.build/design-studies/menubar-icons.png" swift test --filter menuBarNativeLayoutRendersAtPopoverSize
```

During release preparation, convert the reviewed light overview and commit it with the release version change; skip the asset commit if its bytes are unchanged:

```sh
cwebp -lossless .build/design-studies/menubar-preview.png -o docs/assets/menubar-preview.webp
```

The separate icon-strip asset can be regenerated when its documented appearance changes:

```sh
cwebp -lossless .build/design-studies/menubar-icons.png -o docs/assets/menubar-load-icons.webp
```

`cwebp` is an optional documentation tool (Homebrew `webp`), not an app/build dependency.

The render produces light appearance at the requested path and dark appearance at its `-dark.png` sibling; AppKit supplies native typography and controls. Keep the dark panel render as temporary validation output; only the light panel screenshot belongs in README and the tracked assets.

README displays the image at 620 × 560 points; retain up to 2× pixel density. Inspect the output for clipping and spacing; keep each optimized WebP below 200 KB.

The additional 300 × 92-point icon strip uses synthetic levels in borderless buttons, with explicit light/dark tints; it shows startup geometry and CPU load levels, not an actual status bar capture. This is an offscreen panel capture, without simulated menu bar chrome; it does not validate anchoring, dismissal, keyboard focus or Automation. Successful image encoding alone is not a visual oracle.

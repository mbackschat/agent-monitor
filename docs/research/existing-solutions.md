# Existing solutions and reusable code

Research date: 2026-10-14. This is a source review, not an installation, runtime benchmark, or endorsement. GitHub default-branch trees, license contents, repository metadata, and release metadata were fetched directly; important implementation links below are pinned to the observed commits. A recent push demonstrates activity, not correctness. No fetched activity date was later than the research date.

## Which existing tools already address this problem?

### Takeaway

Several direct competitors already combine agent sessions with CPU, RAM, and subprocess trees. Evaluate **agent-top**, **claude-top**, and **tidewake** before committing to a new implementation: they offer, respectively, a reusable Rust core, the closest native Swift architecture, and strong evidence-based attribution of detached processes. These are recommendations from the source review, not measured rankings.

Agent-top's core documentation explicitly separates logical Codex subagents from OS ancestry and reports the method used to join a process to its session. This is valuable because several logical sessions can share one process; assigning that process's full memory to every logical child would overcount. [Core contract](https://github.com/kannandreams/agent-top/blob/5961bf0087d9f827bc4963a8d00c3780000a3ad1/crates/agent-top-core/README.md), [process forest](https://github.com/kannandreams/agent-top/blob/5961bf0087d9f827bc4963a8d00c3780000a3ad1/crates/agent-top-core/src/process.rs).

Additional discovery leads include [jiweiyeah/AgentMonitor](https://github.com/jiweiyeah/AgentMonitor), [wrxck/agenttop](https://github.com/wrxck/agenttop), [tech4242/agenttop](https://github.com/tech4242/agenttop), [CenCiviC/AgentBar](https://github.com/CenCiviC/AgentBar), [rotorrest/claude-monitor](https://github.com/rotorrest/claude-monitor), and [0x0funky/Agentinel](https://github.com/0x0funky/Agentinel). Their READMEs advertise resource or process visibility, but their attribution implementations and licenses were not audited here. Similarly named projects are distinct repositories; preserve owner/repository identities in subsequent evaluation.

[CodeStatus](https://github.com/henriquegpb/codestatus) is useful adjacent inspiration: it explicitly uses lifecycle hooks to distinguish work from waiting and uses process observation for discovery, enrichment, and exit detection. It is a Swift macOS status product under [MIT](https://github.com/henriquegpb/codestatus/blob/main/LICENSE), rather than an answer to detailed CPU/RAM attribution by itself. Token/cost dashboards and “is the agent busy?” monitors should not be confused with measurements of host resource use.

### Inferences

- **Reuse recommendation:** do not select a wholesale fork yet. First evaluate the existing tools against the user's attribution cases. If Rust is selected, prefer testing `agent-top-core` as a pinned dependency before building another discovery layer. If Swift is selected, prefer a small native collector using selectively adapted claude-top/corral code and tidewake's evidence model; importing a Rust runtime boundary solely for process enumeration is unlikely to justify itself. This is an engineering recommendation, not a completed compatibility assessment. [Core API](https://github.com/kannandreams/agent-top/blob/5961bf0087d9f827bc4963a8d00c3780000a3ad1/crates/agent-top-core/README.md), [Swift collector](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/Sources/ClaudeTopKit/ProcessTable.swift).
- **Recommendation:** compare agent-top JSON and claude-top JSON against the same concurrent-session fixture before deciding whether this repository needs a new collector. Both already expose machine-readable views, making a concrete buy-versus-build comparison inexpensive. [agent-top](https://github.com/kannandreams/agent-top), [claude-top](https://github.com/mbrummerstedt/claude-top).
- The likely differentiator is trustworthy attribution and understandable threshold reporting, rather than merely drawing CPU/RAM rows. Retaining unknown or ambiguous ownership is more useful than forcing two sessions in one project into one “responsible” row. This follows from the explicit heuristic joins and evidence tiers in [agent-top-core](https://github.com/kannandreams/agent-top/blob/5961bf0087d9f827bc4963a8d00c3780000a3ad1/crates/agent-top-core/README.md) and [tidewake](https://github.com/berkkorkmaz/tidewake/blob/7dcb8d83a5b9c5e869c3b39ba75c2fc12d1f7076/internal/attrib/attrib.go).

### Gaps

No candidate was installed or run against the user's active sessions. Correctness under multiple sessions in the same cwd, resume/clear, PID recycling, privilege changes, environment scrubbing, very short processes, and shared MCP services remains unverified. CPU overhead, battery impact, and memory footprint claims are not comparable benchmarks. Source review did not establish a complete existing solution for every one of these cases.

## Which general monitors and libraries are worth reusing?

### Takeaway

Prefer a library over extracting a full monitor when the language choice permits it: **sysinfo** for Rust or **psutil** for a Python feasibility probe. For Swift, study the small native collectors in claude-top and corral, then use Stats for later menu bar presentation. The generic projects below do not supply coding-agent session attribution in their documented core purpose.

The inspected sysinfo implementation protects its own process refresh against a changed process start time, refreshes CPU from deltas, reads cwd using `PROC_PIDVNODEPATHINFO`, and obtains arguments/environment using `KERN_PROCARGS2`. These are concrete implementation assets, not inferred macOS capabilities. [Backend source](https://github.com/GuillaumeGomez/sysinfo/blob/515e40d86be11dd9ffb4aa073888eb0a03f4dc0b/src/unix/apple/macos/process.rs).

The current macmon sampler distinguishes footprint-based native process memory from RSS fallback data and measures CPU across sampling intervals. It also tests the imported rusage structure's size and offsets. This is useful evidence for treating metric provenance and foreign-function layout validation as part of the data contract. [Process sampling source](https://github.com/vladkens/macmon/blob/eb6ab687abbedb3ad21f69c6c04365ea1a3ebe00/src/app/procs.rs).

### Inferences

- For a Swift implementation, adapting permissively licensed native collector code is likely simpler than linking Rust just to enumerate processes. For a Rust implementation, agent-top-core plus sysinfo deserves evaluation before rewriting discovery and process grouping. These judgments depend on the still-unselected implementation language. [Swift collector](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/Sources/ClaudeTopKit/ProcessTable.swift), [Rust core](https://github.com/kannandreams/agent-top/blob/5961bf0087d9f827bc4963a8d00c3780000a3ad1/crates/agent-top-core/README.md).
- MIT/BSD/Apache candidates generally offer fewer reuse constraints than GPL code, but copying code still requires satisfying the applicable notice/license conditions and checking dependencies and file-specific notices. A repository license badge is insufficient, and this report is not a completed dependency or distribution compliance audit. [MIT example](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/LICENSE), [BSD example](https://github.com/giampaolo/psutil/blob/01bb959957d99e582b0f391534bb7462f29ff17e/LICENSE), [Apache example](https://github.com/aristocratos/btop/blob/main/LICENSE), [GPL example](https://github.com/htop-dev/htop/blob/main/COPYING).

### Gaps

The comparison does not establish App Store eligibility, entitlement approval, Intel compatibility for every dependency, or the best minimum macOS version. No full transitive license audit was performed. Source paths identify promising reusable components, not a promise that they can be copied unchanged into this repository.

## Which source mechanisms and maintenance evidence should guide a decision?

### Takeaway

Reuse the strongest current mechanisms, not entire assumptions from a competitor. Explicit provider session IDs, historical process identity, measured CPU intervals, and disclosed uncertainty are more valuable than broad feature counts. Read-only inspection should remain the research baseline; cleanup, process killing, and automatic reaping are separate product scope.

### Cited Findings

1. **Prefer documented session stamps over optional socket-path conventions.** Claude documents `CLAUDE_CODE_SESSION_ID` in tool, hook, and stdio MCP subprocesses, with clear/resume and already-running MCP caveats. The messaging socket exists only for sessions binding an inbox, from v2.1.224 onward. This qualifies claude-top's broad README claim that every child has a socket stamp. [Official environment reference](https://code.claude.com/docs/en/env-vars), [claude-top environment reader](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/Sources/ClaudeTopKit/ProcessEnvironmentReader.swift).
2. **Keep attribution evidence explicit.** Tidewake's rules use `CLAUDE_CODE_SESSION_ID` and `CODEX_THREAD_ID`; its classifier distinguishes known leftovers, detached work, uncertainty, and path-based suspects. The Codex variable in these rules is upstream application usage evidence, not by itself an official stability guarantee. [Rules](https://github.com/berkkorkmaz/tidewake/blob/7dcb8d83a5b9c5e869c3b39ba75c2fc12d1f7076/internal/rules/pack.json), [classification](https://github.com/berkkorkmaz/tidewake/blob/7dcb8d83a5b9c5e869c3b39ba75c2fc12d1f7076/internal/attrib/attrib.go).
3. **Retain both PID and process birth identity.** Corral caches executable paths, terminals, and arguments against PID plus start time, and uses kernel wall-clock start information rather than deriving age across sleep from a monotonic clock. Borrow this guard before adding persistent history. [Scanner](https://github.com/popyapp/corral/blob/39ba7680fb18f79b9f824274d8446e8e18d16c8b/Sources/Corral/ProcessScanner.swift).
4. **Calculate resource values over explicit intervals.** Claude-top reads cumulative user/system CPU time and RSS through `PROC_PIDTASKALLINFO`, then calculates deltas; a 25% threshold needs this interval definition and a specified normalization. Its source deliberately distinguishes missing deltas from valid zero values. [Process table](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/Sources/ClaudeTopKit/ProcessTable.swift), [delta calculation](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/Sources/ClaudeTopKit/AttributionEngine.swift).
5. **Keep context narrow.** Claude-top extracts an allowlist from raw environment entries instead of retaining every variable. Tidewake and agent-top show that useful ownership context can be separated from transcript content and resource sampling. Treat environment secrets, command arguments, and prompts as data-minimization concerns during design. [Environment reader](https://github.com/mbrummerstedt/claude-top/blob/d088212b58ad7a9b8d424ca283e4aef90224227e/Sources/ClaudeTopKit/ProcessEnvironmentReader.swift), [core interface](https://github.com/kannandreams/agent-top/blob/5961bf0087d9f827bc4963a8d00c3780000a3ad1/crates/agent-top-core/README.md).

### Inferences

The next useful evaluation is a small reproducible scenario matrix: two sessions in one directory; a shell launching a busy grandchild; detached child surviving agent exit; nested agent; shared long-lived MCP; process exit between samples; and restart/PID reuse. Compare ownership evidence, individual and aggregate CPU/RAM, unknown states, and collector overhead. This is a recommendation for later validation, not work performed in this research.

Do not copy a competitor's cleanup feature just because its attribution code is useful. Neither a cwd match nor an inherited stamp proves that a long-lived desktop application is unwanted; tidewake explicitly protects user applications even when they inherited agent markers. The present request concerns diagnosis. [Application ownership guard](https://github.com/berkkorkmaz/tidewake/blob/7dcb8d83a5b9c5e869c3b39ba75c2fc12d1f7076/internal/attrib/attrib.go).

### Gaps

Current README claims and implementation behavior can diverge, and default branches can outpace released builds. This review identifies one concrete divergence to avoid propagating: the universal Claude socket-stamp assumption versus the official conditional socket contract. A dependency decision should pin and test a release or commit and preserve the provenance of copied code. No code was imported, tool installed, user process inspected, or process terminated for this report.
